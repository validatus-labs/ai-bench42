# Evaluation and freeze contract — Brave offline ModelBench

**Status: TASK CONTRACT APPROVED / RUNTIME NOT READY / NOT STARTED.** This document defines the approved Brave-based offline coding benchmark; the coordinator MUST pin and independently verify the exact offline source SHA and worker controls before trials. Old `benchmark/base-v1` and `benchmark/base-v2` remain prior baselines and are not automatically replaced.

1. **Immutable assignment:** verify exact tree, instructions, tests, model catalog and budgets before creating any candidate trial. Existing dirty/changed/ambiguous state must fail closed—not silently reset, clean or overwrite.
2. **Research-tool parity:** pin the actual approved **Brave + Playwright + MCP** binary hashes, server/tool schema, configuration, runtime identity, separately enforced docs-only origins, service-worker blocking and network/worker isolation. Demonstrate a real MCP tool-call from each candidate model, not only the earlier host-open Kolibri session. No Chromium install/fallback as a side effect. All candidates must receive the same browser affordances, budgets and URLs; log blocked/retried navigation. Browser origin filtering does not create a firewall.
3. **HPI development data:** if approved, supply only the exact 12-pair ASF/TRAIN visible bundle SHA from `tools/greenfield.py hpi-bundle` to each worker. Missing privacy approval or a different bundle blocks comparable real-corpus trials. Hold out independent HPI TEST/EVAL, prohibited reference code and private Gold.
4. **Models and seeds:** each eligible model gets the same source snapshot, prompts/test data/tool permissions and the seeds 1/2/3. The model catalog is illustrative, not a claim that every backend can run. Pin exact model checkpoint, tokenizer, serving setup, context and quantization in a per-run manifest.
5. **Separate execution:** enforce isolation outside Git. Workers must not access reference implementation, competitor source, corpus/HPI Gold, hidden tests, other runs, host HOME, Git credentials, shared Git object stores or unrestricted network endpoints.
6. **One result branch per model × seed:** a worker uses a Git-free isolated export; after freeze the coordinator may preserve code in `trial/<model-slug>/seed-<n>`. Never continue another model's branch; divergent state requires a new Run-ID.
7. **Idempotence:** same source/config/test/model/seed fingerprint => verify/reuse complete artifacts. Different input => new Run-ID, never overwrite earlier metrics. Keep raw bounded logs and unsuccessful attempts.
   Historical receipts created with seeds 41/42/43 belong to earlier, separately pinned cohorts. Never relabel or reuse them as seed-1/2/3 trials.
8. **Candidate implementation:** frozen fixture/API safety contract, rules-only parser, `authorized_removals=[]`. A proposed backward-compatible `ml_mode="off"` flag and a **reserved/unsupported** `recover` mode are tested only for interface design; no classifier inference/training or weights are allowed. Include a minimal local offline CLI with `--ml-mode off|recover` as documented in [BUILD_CONTRACT.md](BUILD_CONTRACT.md). Initial scaffold checks pass; initial acceptance fails by design; candidate must make acceptance pass without changing tests.
9. **Independent evaluation:** freeze final candidate tree. Only evaluator sees rights-cleared HPI Gold/hidden tests; report TP/FP/FN/F1, exact boundaries, abstentions, source preservation and unsupported cases without self-certification.
10. **Separate scores:** serving metrics (AIPerf), general IFEval/MMLU-Pro/BBH, SWE-bench/BFCL and Melusense applied coding are complementary measures. Report code quality and run cost separately.
11. **No classifier gate:** training an FN logistic classifier, Synthetic FN, model-based deletion or extra LLM inference is not part of this benchmark. The explicit off-only/recover-unsupported interface may be scored narrowly under API extensibility, **never as ML detection accuracy**. Actual classifier research needs its own separately frozen experiment.
