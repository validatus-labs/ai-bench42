# AI-Bench42 — portable offline coding-agent prompt (ENGLISH)

This is the reusable candidate-facing instruction. The coordinator verifies the offline package SHA and worker isolation before handing it to a model.

> **MODEL-AGNOSTIC INSTRUCTION — copy unchanged for every model and seed**
>
> You are a coding agent participating in AI-Bench42 Phase 4. Work **only** in the isolated local offline `/workspace` provided by the coordinator. You have no Git credentials or repository clone access; public source pages may be read through the approved browser. Use the identical, independently approved frozen assignment, fixed seed, tool permissions and resource limits recorded in your read-only run manifest.
>
> **C00 / preflight:** Read `MANIFEST.md`, `TASKS.md`, `AGENTS.md`, `docs/CONTRACT.md`, `docs/EVALUATION.md`, `docs/RUNBOOK.md` and the frozen visible tests. Confirm the coordinator's signed-off package SHA-256, run fingerprint, exact served model ID/revision, budgets, toolchain manifest and effective worker/network isolation. Confirm the required approved 12-pair HPI TRAIN bundle matches the shared SHA-256 in your run manifest. Verify that **your agent**, not only a standalone browser process, can invoke the approved pinned Brave/Playwright/MCP tool on a harmless local `data:` page. Public HTTPS research for client formats, languages and parser/regex examples uses that browser under the externally enforced policy in `docs/RUNBOOK.md`. Never access the private original Melusense implementation, other model trials, private Gold, HPI TEST/EVAL, GitHub credentials or host HOME.
>
> If a mandatory gate is absent or a version/hash differs, write a **redacted BLOCKED/DEVIATION receipt** in your own `build/`, explain exactly what is missing and **stop before C01**. Never reinstall, update, restart a server, weaken security, switch browser engines, edit frozen assignment/tests or invent an approval.
>
> **C01–C07 / implement only after verified READY:** Run the scaffold checks and record the *expected failures* of the initially unimplemented acceptance tests. Research Gmail, Outlook, Thunderbird, Apple Mail/iPhone and named Android-client formats plus language variants and public parser/regex examples. Record URL, date and license/provenance for adapted rules; test positive cases and negative lookalikes. Independently design and implement the multilingual rule-first email parser using safe inert MIME/charset processing, immutable Unicode/CRLF source views, TOML dictionaries, bounded regex for EN/DE/FR/ES, reply/forward/signature/footer processors and a deterministic BoundaryReviewer. Add further locales only with evidence and tests. Implement the exact public API and structured results in `docs/CONTRACT.md`. Keep `authorized_removals=[]` unconditionally; uncertain evidence must abstain, never delete message text or invent raw-byte offsets.
>
> **Reserved classifier switch, not training:** Support the proposed public `ml_mode="off"` option **and** the minimal local `python -m melusense ... --ml-mode off|recover` CLI. `off` is the only executable mode and must behave identically to the default rule-only parser. Recognize `ml_mode="recover"` only as a **reserved future extension**: fail clearly and deterministically as `NOT_IMPLEMENTED` or `UNSUPPORTED`. Do not load weights, invoke a classifier/LLM, train, fine-tune, synthesize labels or silently fall back. No classifier performance is evaluated in this phase.
>
> Do not change frozen tests, fixtures, config, `TASKS.md` or `AGENTS.md`. You may add new adversarial tests. Follow the prescribed candidate source tree (including required module names), with no model-specific wrapper folders. Store your source changes inside your own workspace and a complete `build/worker-report.json` containing Run-ID, versions, source hashes, decisions, visible test results, all failures, tool calls, tokens, elapsed time and limitations.
>
> Before freezing, run your parser on all 12 supplied HPI TRAIN examples and record per-example results and failures, the bundle SHA-256 and any annotation mapping in `build/worker-report.json`. These checks are development evidence. Freeze the candidate and stop. Only the independent evaluator may run sealed hidden tests and qualified Gold scoring. Do not self-certify success. Same fully verified Run-ID/input fingerprint: reuse complete outputs without overwriting; changed inputs require a new, coordinator-approved Run-ID.

## Scope and execution notes (coordinator only)

- This instruction is intended to be **identical for Kolibri-1, Mistral Small 4, GLM-5.3 Flash, Qwen, and other eligible agents**. Substitute **no model-specific text** in the task itself; manifest and sandbox routing carry the identity and seed.
- The coordinator retains `evidence/`, `reports/` and `evaluator-private/` **outside** worker-visible mounts. The worker may write only `/workspace/build/`.
- P4 build-module paths are in `AGENTS.md`; the reserved mode contract is in `docs/CONTRACT.md`. All agents receive the same frozen source version before trials.
- The offline package/build has no Git clone or credentials. Public client documentation and public source pages, including GitHub, may be read through the approved Brave MCP only; an effective external egress policy blocks private/internal destinations and disallowed operations.
- HPI TRAIN is **required for every Phase-4 model and seed**. Supply the identical rights- and worker-disclosure-approved 12-pair bundle and record its SHA-256. Missing approval, missing data or a checksum mismatch blocks C00. Protected evaluator Gold always stays sealed.
