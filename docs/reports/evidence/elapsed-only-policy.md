# Measuring duration without a whole-trial deadline

For new trials, an explicitly versioned execution profile removed the overall
one-hour wall deadline. The old assignment and old results remained unchanged;
new manifests disclosed the timing override. Backend and observer lifetimes were
configured without a total duration cutoff.

Request, tool, generated-token, memory/process and individual idle/tool bounds
remained. Removing wall time did not create unlimited resources or permission to
replay an uncertain request. New receipts measured coding time separately from
preparation/readiness and whole-trial time.

Local controller regressions and 55 applicable native checks passed. Simulated
clocks covered more than eight hours; a short service-property probe checked the
infinite lifetime setting. Neither was an eight-hour live inference experiment.
Read-only reuse checks made no model requests. A fresh qualified coding attempt
was still required to evaluate behavior under the changed policy.
