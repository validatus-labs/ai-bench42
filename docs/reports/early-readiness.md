# Early coding readiness: missing evidence

The initial coding preflight was BLOCKED before candidate development. Several
similarly named baseline references contained different source content. Choosing
a source revision resolved the selection question, not runtime readiness.

The installed Brave browser worked, but the selected historical contract required
a different Chromium toolchain. A documented installation destination was merely
an intended location, not proof that the required software existed there.
Agent tool use, actual worker isolation, approved TRAIN inputs, other model
endpoints and the independent evaluator each required their own evidence.

Subsequent browser diagnostics and a new Brave baseline addressed parts of these
gates in separate reports. They do not retroactively convert this initial check
into READY. Existing P1–P3 measurements and calibration were reused rather than
rerun without cause. Missing held-out Gold means NOT_EVALUATED, not zero error.
No candidate coding began during this preflight.
