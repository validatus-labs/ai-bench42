# Results — What can these models actually deliver?

**Kolibri produced useful, tested code and used tools successfully. None of the
reviewed trials delivered the complete parser.** This is a practical development
case study, not a general verdict that Kolibri cannot code.

We test how published coding ability translates into complete software, and how
much review and correction the work needs. The first task is a multilingual email
parser for potential ERP, reply-drafting and reporting workflows: preserve original
content, handle MIME safely and connect all required components into one interface.
Business savings and German application quality remain unmeasured. Reported model
trials concern Kolibri; other contenders await a matched local comparison.

| Reader question | What the evidence currently supports |
| --- | --- |
| Can Kolibri write code? | Yes: all 21 supplied and ten worker-authored tests passed in the latest independent attempt. |
| Can it use tools? | Yes in the checked cases, including real browser calls; sustained workflow reliability is a separate question. |
| Did it finish the complete task? | No: 24/27 supplemental probes passed, but integration and safety requirements remained incomplete. |
| Did guidance solve this? | The guided trial made partial progress and remained incomplete; changed conditions prevent a causal claim. |
| Did cache calibration improve quality? | Results were mixed on the small general-evaluation selection. |
| Would Mistral or GLM finish it? | Not established: no matched local project comparison is available. |
| Did the agent save human time? | Not measured against a human baseline. Trial durations and review rounds alone cannot establish savings. |
